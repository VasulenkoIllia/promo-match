# promo-match

Створено за стандартом бази (/new-project, 2026-10-28).

Вимоги: docs/requirements.md. Бриф клієнта лежить у `brief/` лише локально: не в git і не в Docker-образі.

## Локально
- Node 26: `nvm use`.
- pnpm 12.14.0 з `packageManager` у package.json: якщо pnpm для цього Node немає, один раз `npm install --global --allow-scripts=pnpm pnpm@12.14.0` (corepack у Node 26 немає); pnpm іншої версії сам завантажить цю.
- `pnpm install`. Скрипти встановлення залежностей не запускаються: кожен пакет зі скриптом стоїть у `allowBuilds` файла `pnpm-workspace.yaml` з `false`, тож пакет із npm не виконає свій код при встановленні. Новий пакет зі скриптом зупиняє `pnpm install`, доки в список не додано його рядок: `false`, або `true` з причиною поруч, якщо без скрипта пакет не працює. `dangerouslyAllowAllBuilds: false` там же не дає глобальному налаштуванню pnpm зняти цю зупинку; змінні середовища `pnpm_config_*` сильніші за файл, тож налаштувань збірки ними не задавати. `ignore-scripts=true` у `.npmrc` лишився для npm і npx, запущених помилково.
- Аргументи скрипту йдуть одразу після його назви, без `--`: `pnpm run import:catalog --dry-run`. pnpm передає `--` у скрипт, прапорців після нього скрипт не розпізнає й зупиняється з помилкою, нічого не зробивши.
- `cp .env.example .env`.
- У `.env` заповнити `POSTGRES_PASSWORD` (літери й цифри) і той самий пароль у `DATABASE_URL` замість `<POSTGRES_PASSWORD>`.
- Решта ключів `.env` уже має робочі значення для локального запуску; сервер: docs/deployment.md.
- `pnpm run db:up`: Postgres у Docker на 127.0.0.1:5432, команда чекає, доки він готовий. Порт зайнятий іншим проєктом: у `.env` інший `POSTGRES_PORT` і той самий порт у `DATABASE_URL`.
- `pnpm run db:migrate`: генерує Prisma-клієнт і застосовує міграції з `prisma/migrations`; потрібно й на свіжій копії репо, до `pnpm run dev`.
- Моделі в `prisma/schema.prisma`; після зміни схеми `pnpm run db:migrate --name add_orders` (назва міграції латиницею, без `--`: pnpm передав би його Prisma) створить і застосує нову міграцію. Файли з `prisma/migrations` комітяться разом зі схемою.
- `pnpm run db:down` зупиняє Postgres, дані лишаються в томі Docker.
- `pnpm run users add <логін> --role admin`: перший адмін, пароль запитається двічі; далі він запрошує людей на екрані (розділ «Користувачі й вхід»).
- `pnpm run dev`
- В іншому терміналі `pnpm run dev:web`, відкрити адресу, яку покаже Vite, і увійти.

## Smoke-тест API постачальників
- У `.env` заповнити змінні постачальників з `.env.example`: Axpol і Midocean, з 2026-11-04 ще Makito, Inspirion, Blue Collection. API бойові, акаунти можуть створювати замовлення; скрипт лише читає.
- `pnpm run smoke:suppliers --dry-run`: план запитів без мережі.
- `pnpm run smoke:suppliers`: логін і читання API, зразки й структура відповідей в `output/smoke-test/` (поза git). `--only makito,inspirion` запускає перелічених постачальників, змінні потрібні лише їхні. Подробиці: docs/integrations.md.

## Імпорт каталогів
- Ті самі ключі в `.env`, БД запущена й з міграціями (`pnpm run db:up`, `pnpm run db:migrate`).
- `pnpm run import:catalog --dry-run`: читає API постачальників і БД, друкує план (нові, змінені, зниклі рядки) і нічого не пише.
- `pnpm run import:catalog`: повний імпорт усіх підключених каталогів (Axpol, Midocean, Inspirion, Blue Collection, Makito, Anda Present), повторний запуск безпечний; потрібні змінні всіх шести. `--only inspirion` (чи `axpol`, `midocean`, `bluecollection`, `makito`, `anda`) для одного постачальника; `--probe` лише перевіряє ліміти API.
- Anda Present віддає фіди лише IP сервера. На Mac: `ANDA_FEED_DIR=<тека> pnpm run import:catalog --only anda --dry-run` читає 4 фіди, збережені через тунель власника, без токена; команда збереження в docs/integrations.md, «Anda Present XML». Повний імпорт на Mac без `ANDA_FEED_DIR` читає Anda з мережі й отримує 403 (решта постачальників іде далі, код виходу 1); без `ANDA_FEED_TOKEN` і `ANDA_FEED_DIR` worker зупиняється з `ConfigError` ще до читання.
- Macma й Easy Gifts лише разово й окремо: `pnpm run import:catalog --only macma`, потім `--only easygifts` (фіди XML з магазину клієнта, їхні адреси в `.env`: `MACMA_FEED_URL` і `EASYGIFTS_FEED_URL`, бо репозиторій публічний). Без `--only` імпорт їх не читає; залишків у них немає.
- Що й як пишеться, деактивація зниклого, захист від подвійного запуску: docs/integrations.md, «Імпорт каталогів». На сервері: docs/deployment.md.

## Ембедінги каталогу
- Після імпорту. Виклики провайдера платні: у `.env` `EMBED_PROVIDER` (`voyage` чи `gemini`), його ключ (`VOYAGE_API_KEY` чи `GEMINI_API_KEY`) і ліміт витрат на запуск `EMBED_BUDGET_USD` у доларах.
- `pnpm run embed:catalog --dry-run`: скільки фото й текстів піде і скільки це коштує за прайсом, без викликів і запису; без `EMBED_PROVIDER` рахує обидва провайдери.
- `pnpm run embed:catalog`: вектори фото й текстів усіх постачальників, повторний запуск рахує лише нове й змінене; без `--only` бере й нових постачальників, тобто платить і за них. `--only axpol`, `--limit 100` для пробного запуску, `--retry-failed` знову бере фото зі статусом `failed`.
- `pnpm run embed:compare --dry-run`, потім без прапорця: порівняння провайдерів на зразку 200 моделей, звіт в `output/embeddings-compare/`.
- Подробиці: docs/integrations.md, «Ембедінги каталогу» і «Модель ембедінгів». На сервері: docs/deployment.md.

## Спільні категорії

- Подробиці: docs/integrations.md, «Спільні категорії».

## Пошук
- Після ембедінгів, з міграціями індексів (`pnpm run db:migrate`). Ключ провайдера моделі в `.env` (`GEMINI_API_KEY` чи `VOYAGE_API_KEY`); ліміт витрат пошуку на добу `SEARCH_BUDGET_USD`, порожній означає $1.
- Текст запиту перед пошуком читає Claude (переклад англійською й підказки фільтрів): ключ `ANTHROPIC_API_KEY`, модель `QUERY_PARSE_MODEL` (порожня означає `claude-haiku-5-5`), ліміт на добу `QUERY_PARSE_BUDGET_USD` (порожній означає $1). Без ключа пошук іде текстом як є, крім уже прочитаних текстів: читання лежить у таблиці `query_reading`, тож той самий текст дає ту саму видачу без платного виклику, зокрема після перезапуску сервера. Хибне читання так само закріплене; як його скинути, у docs/integrations.md, «Claude API».
- `pnpm run search --text "red ceramic mug"`, `--image <файл.jpg>` чи обидва; `--model all` проганяє запит через обидві моделі, фільтри `--source`, `--shared-category drinkware.mugs` (код спільної категорії чи групи), `--category "axpol:DRINKWARE > ceramic mugs"` (шлях постачальника), `--min-stock 500`; `--limit 100` (скільки моделей вивести, типово 24, найбільше 100), `--lists text-text` (лише названі списки), `--json` (вивід у JSON); `--no-parse-query` шукає текстом як є, `--parse-model claude-sonnet-5-5` читає запит іншою моделлю, `--condition-pass` вмикає другий прохід за фактами каталогу, як перемикач екрана. У виводі закупівельні ціни: не комітити.
- API: `pnpm run dev`, далі `POST /api/search` і `GET /api/search/options`, лише після входу (розділ «Користувачі й вхід»). Понад 20 пошуків за хвилину на користувача відповідь 429 (`SEARCH_RATE_PER_MINUTE`).
- Подробиці: docs/integrations.md, «Пошук».

## Веб-інтерфейс пошуку
- Лише для комп'ютера. `pnpm run dev` і в іншому терміналі `pnpm run dev:web`, далі адреса, яку покаже Vite (http://localhost:5173), і вхід. На сервері той самий екран віддає застосунок. Фото Makito екран бере через сервер (`/api/photos/makito/`), бо Makito віддає їх лише з токеном: `pnpm run dev` потрібні `MAKITO_CLIENT_ID` і `MAKITO_CLIENT_SECRET` у `.env`. Фото Macma й Easy Gifts теж через сервер (`/api/photos/promotray/`): це файли архівів ZIP, змінних не треба.
- Фото: обрати файл (JPEG, PNG чи WebP), перетягнути на блок «Фото-референс» чи вставити з буфера (Ctrl+V). Рамкою мишкою обвести товар, без рамки в пошук іде все фото. Опис будь-якою мовою, Ctrl+Enter запускає пошук.
- Фільтри: постачальники, спільна категорія (група чи категорія, кнопка «Додати»), з одним позначеним постачальником ще його власне дерево категорій англійською (розділ чи категорія будь-якого рівня, разом зі спільною через «і»), мінімальний залишок (під ним названо постачальників без даних про залишок, зараз Easy Gifts і Macma: з фільтром їхніх товарів не буде), модель ембедінгів (лише Gemini: векторів Voyage мають лише Axpol і Midocean), перемикач «Піднімати товари, де каталог підтверджує умови запиту» (типово вимкнений: факти в постачальників неповні по-різному, тому без нього порядок лише за схожістю, однаковий для всіх; він вмикає другий прохід за об'ємом, розміром, технікою друку й аркушами, позначки на картці є і без нього), «Точні умови»: об'єм, матеріал чи розмір, які додала кнопка над результатами («Показати лише ті, де каталог це підтверджує»), далі лише товари, де каталог підтверджує умову, «×» умову прибирає. Кожен пошук платний (ембедінг запиту, для тексту ще розбір Claude), тому пошук лише кнопкою.
- Над результатами переклад запиту й підказані категорії: клік додає категорію у фільтри й шукає знову. Ціни на екрані закупівельні: скріншоти не комітити.
- На картці відповідність умовам запиту, окремо для об'єму, матеріалу, розміру, техніки друку, аркушів і щільності: «підходить», «не перевірено» (каталог цього не каже), «не підходить». Лише те, про що запит питає; рахує код за полями каталогу, без оплати, сама позначка порядку видачі не міняє. Запит із кількома товарами: картка порівнюється з товаром, чий пошук дав моделі місце. Модель, яку знайшов лише артикул, позначок не має. Правила: docs/integrations.md, «Об'єм, матеріали, розміри» і «Техніка друку».
- Коли за текстом немає нічого близького, над результатами рядок «Близького збігу не знайшов»: це лише підказка, видача та сама (поле `hasCloseMatch`, лише для Gemini, лише для тексту без фото й без фільтрів екрана, коли читання назвало товар).
- Над сіткою вартість цього пошуку за прайсом: вектори запиту й читання Claude (поле `costUsd`). Збережене читання не оплачується, тож той самий текст удруге дешевший, а пошук лише за кодом без оплати. Це оцінка, рахунок провайдера може відрізнятись.
- Над сіткою вибір «Показати»: 12, 24 (типово), 48 чи 100 моделей. Пошук завжди приносить 100, екран лише обрізає, тож перемикання не платне й не міняє порядок. На картці «Впевненість N%» і слово (розділ «Впевненість»).
- На картці посилання «На сайті постачальника». Вигрузки адреси не дають, вона складена за правилом сайту, тому на Axpol близько 8% посилань ведуть на 404 (docs/integrations.md, «Сторінка товару»).
- На картці кнопки «Саме те», «Можна запропонувати», «Не те»: оцінка зберігається в БД разом із текстом запиту, повторний клік її забирає (docs/integrations.md, «Оцінки»). Новий пошук починається без оцінок.
- Рядки інтерфейсу в `web/src/text.ts`. Рішення: docs/decisions.md, 2026-10-30.

## Свої товари
- Після міграцій (`pnpm run db:migrate`). Той самий веб-інтерфейс, вкладка «Свої товари»: перелік, створення (назва, необов'язковий артикул), відв'язування. Викликів до платних API немає.
- У картці результату пошуку кнопка «Прив'язати до свого товару»: обрати товар чи «Новий товар» і тип зв'язку («Той самий» чи «Аналог»). Прив'язана модель має позначку в картці, одна модель може належати кільком своїм товарам. Повтор тієї самої пари з іншим типом міняє тип.
- API лише після входу, як і пошук: `GET` і `POST /api/own-products`, `GET /api/own-products/links?modelIds=1`, `PUT` і `DELETE /api/own-products/:ownProductId/links/:modelId`. Подробиці: docs/integrations.md, «Свої товари».

## Постачальники
- Вкладка «Постачальники» (адміну й менеджеру): по кожному постачальнику каталог, останній імпорт, свіжий залишок, вектори Gemini й моделі без спільної категорії; рядки, які потребують уваги, підсвічені. Екран лише читає БД, імпорт і вектори запускаються командами вище.
- API: `GET /api/suppliers` після входу. Подробиці: docs/integrations.md, «Постачальники».

## Користувачі й вхід
- Після міграцій (`pnpm run db:migrate` чи `pnpm run db:deploy`). Самостійної реєстрації немає. Ролі: адміністратор запрошує, вимикає й скидає пароль; менеджер шукає, оцінює й прив'язує свої товари. Користувачі, що були до ролей, стали менеджерами.
- `pnpm run users add <логін> --role admin`: адмін, без `--role` менеджер. Логін малими латинськими літерами, цифрами, крапкою, дефісом чи підкресленням; пароль від 12 до 128 знаків запитується двічі й не показується.
- Вкладка «Користувачі» (лише адміну): «Створити посилання» з роллю дає одноразове посилання на 72 години, його копіюють кнопкою й надсилають самі. Людина відкриває його, обирає логін і пароль, далі входить. «Скинути пароль» дає таке саме посилання на новий пароль, після нього всі входи людини закриваються. «Вимкнути» закриває вхід одразу; себе вимкнути не можна. Пошти не зберігаємо, листів не шлемо.
- На сторінці посилання 5 спроб на посилання і 30 на адресу за 15 хвилин, далі 429.
- `pnpm run users password <логін>`: новий пароль. `disable <логін>`: вхід вимкнено. Обидві команди закривають усі сесії користувача. `enable <логін>` вмикає знову, `list` показує всіх з роллю.
- Вхід на екрані, вихід кнопкою «Вийти» вгорі справа. Сесія живе 7 днів від входу, далі знову екран входу; форма й результати пошуку при цьому зникають.
- 5 спроб на логін і 30 на адресу за 15 хвилин, далі 429 і час очікування. Лічильники в пам'яті: перезапуск сервера їх скидає.
- Подробиці: docs/integrations.md, «Логін». На сервері: docs/deployment.md, «Перший деплой» і «Ручні задачі».

## Сценарій демо
Показ екрана пошуку на локальній БД, близько 5 хвилин. Кожен пошук платний (менше цента за прайсом), ціни на екрані закупівельні: показувати лише своїм, скріншоти не комітити.

Перед показом: `pnpm run db:up`, `pnpm run dev`, в іншому терміналі `pnpm run dev:web`, відкрити http://localhost:5173 і увійти. Фото-референс підготувати заздалегідь і перевірити його пошуком.

1. Фото. Перетягнути фото на блок «Фото-референс», натиснути «Шукати». Близько секунди, і сітка моделей: фото, постачальник, ціна, залишок, варіанти.
2. Обрізка. Обвести товар рамкою мишкою, шукати знову. «Усе фото» прибирає рамку.
3. Опис. Додати опис будь-якою мовою, наприклад «кружка з чорною ручкою і малюнком оленя», Ctrl+Enter. Над результатами переклад англійською й підказані категорії.
4. Умови. Опис із числом чи матеріалом, наприклад «скляна пляшка понад 800 мл, розмір 25x8 см»: на картках «Об'єм», «Матеріал» і «Розмір» зі словами «підходить», «не перевірено» чи «не підходить». Сама позначка порядку не міняє, тож картка з «не підходить» може стояти вище: це підказка менеджеру, а прибрати такі товари можна кнопкою умови над результатами. Запит про нанесення, наприклад «вишивка на кепці»: на картках «Друк», у кепок Axpol часто «не перевірено», бо код постачальника ще не пояснений.
5. Фільтри. Клік на підказану категорію додає її у фільтри й шукає знову, поруч постачальники й мінімальний залишок. Спільна категорія йде за категорією постачальника: Midocean тримає кружку CX1571 FESTIMUG у сезонних подарунках, тож фільтр «Кружки й чашки» прибирає її з результатів. Для показу брати товар із його звичайної категорії.
6. Факти каталогу. Для запиту кроку 4 увімкнути «Піднімати товари, де каталог підтверджує умови запиту» і шукати знову: моделі, де каталог підтверджує об'єм, розмір, техніку друку чи аркуші, піднімаються (другий прохід, docs/integrations.md, «Об'єм, матеріали, розміри»). Типово вимкнений, бо ці дані в постачальників неповні по-різному.
7. Артикул. Ввести в опис код постачальника, наприклад `V2233-03`: модель першою з позначкою «Збіг за артикулом», без платних викликів. Код `5246` є в Makito й Easy Gifts: обидві картки з «код є в 2 постачальників» і впевненістю 50%.
8. Кількість і впевненість. У «Показати» обрати 12 чи 100: сітка змінюється одразу, без нового пошуку. На картках «Впевненість N%»: сказати вголос, що це оцінка автоматичних перевірок, люди її ще не підтвердили.
9. Оцінка й сайт. На першій картці натиснути «Саме те», відкрити «На сайті постачальника».
10. Якість. Показати результат із розділу «Тест якості пошуку», коли там буде число: зараз чекаємо випадків клієнта.

Пройдено 2026-10-30 на локальній БД: 5 пошуків, обидві моделі, 0,8-2,2 с на пошук, усі відповіді повні. Крок 4 пройдено 2026-10-31: 2 платні пошуки, Gemini, 3,5-4,3 с, один із них про два товари, позначки на всіх 24 картках кожного. «Друк» і «Аркуші» на картках перевірено 2026-10-31 на кепках і блокнотах; «Щільність» на екрані не бачено, її покриває тест тексту.

## Тест якості пошуку
Реальні запити йдуть через той самий пошук, що й веб-екран (`src/search`: без фільтрів, типовий `limit` 24, текст читає Claude, перемикач фактів вимкнений), і для кожної моделі ембедінгів рахується частка випадків із правильним товаром у топ-10. Вигадані запити реальних не замінюють. `--condition-pass` проганяє з увімкненим перемикачем, без доплати.

- Кошторис і коди нижче писано, коли в каталозі були лише Axpol і Midocean (6,5 тис. моделей). Аналіз 2026-11-06 на 7 постачальниках (15,6 тис. моделей, звіт `output/reports/Критичний аналіз пошуку 2026-11-06.md`, поза git): ті самі змодельовані запити про товари Axpol і Midocean дають свій товар у топ-10 рідше, бо схожих товарів стало більше, текст 205 → 191 із 220, фото-скриншоти 786 → 712 із 1000. Код у таблиці тепер може бути будь-якого з 7 постачальників.
- Випадки готує клієнт: 20-50 реальних запитів, правильний товар названо без погляду на наш пошук (питання 14 у docs/requirements.md). Текст для клієнта й порожня таблиця: `output/quality/for-client/`.
- Усе поза git: таблиця `output/quality/cases.csv`, фото в `output/quality/photos/`, звіти `output/quality/report-<дата>.json` (без цін). Інша таблиця: `--cases <файл>`, фото тоді в `photos/` поруч із нею.
- Колонки таблиці (CSV UTF-8, роздільник кома, крапка з комою чи табуляція, інші колонки не читаються): `id`; `photo`, назва файлу; `text`, запит як є; `same`, коди того самого товару; `analogs`, коди прийнятних аналогів. Код це код моделі чи артикул Axpol або Midocean, кілька через пробіл. У рядку потрібні фото чи текст і хоч один код.
- `pnpm run search:quality --dry-run`: перевіряє таблицю, фото й коди проти БД і друкує кошторис, без викликів провайдерів. Проблеми названі по рядках, і з ними платний прогін не стартує. Товар, який пошук не може знайти (неактивний чи без векторів), теж проблема: такий рядок виправити чи прибрати, інакше він рахувався б промахом пошуку.
- `pnpm run search:quality`: платний прогін обома моделями під лімітами `SEARCH_BUDGET_USD` і `QUERY_PARSE_BUDGET_USD`, що в цього скрипта рахуються на запуск. Потрібні всі три ключі (`GEMINI_API_KEY`, `VOYAGE_API_KEY`, `ANTHROPIC_API_KEY`), без них прогін не стартує. Спершу кошторис і OK власника. На 50 випадках до $0.12 за прайсом, з них Voyage до $0.06 із безкоштовної квоти.
- Два числа на модель: «той самий товар» (лише випадки з `same`) і «той самий чи аналог» (усі випадки), окремо ще для фото, тексту й обох. Влучання рахується до моделі, а не до кольору. Пошук, що не відповів, не входить у частку; прогін його називає й завершується з кодом 1, так само коли Claude не прочитав якийсь текст: таке число не остаточне. На 20-50 випадках різниця моделей в 1-2 випадки нічого не доводить.
- Запити з кодом: правильний код можна брати із самого запиту чи підбору менеджера, але в `text` кода бути не повинно, тест шукає лише за змістом. Запит, де без коду нема за чим шукати, йде в `output/quality/cases-article-only.csv`, у головне число не входить (`--cases <файл>`).
- Відмінність від екрана: без точного збігу за кодом, щоб код не рахувався влучанням. Фото йдуть як є, без рамки й без стиснення до 1024 px. Лише JPEG чи PNG до 8 МБ і 16 Мп. WebP чи HEIC перетворити: `sips -s format jpeg <файл> --out <файл>.jpg`, завелике фото ще з `-Z 1024` (`-Z` збільшує й малі). Екран сам повертає фото за EXIF і кладе прозорий PNG на біле тло, скрипт ні: перед прогоном `sips -g orientation -g hasAlpha output/quality/photos/*`, і фото з `orientation` не 1 чи `<nil>` повернути, а прозорі покласти на біле.
- Результат: числа ще немає, випадків від клієнта чекаємо (рядок сюди: дата, кількість випадків, модель, обидва числа).

## Впевненість
- На кожній картці шанс, що товар саме те, що просили: частка оцінок 3 серед схожих результатів, кроком 5%. Висока від 75%, середня від 45%, низька нижче (поле `confidence`, `src/search/confidence.ts`). Оцінки агентів, не людей. Порядок видачі не змінює, нічого не ховає, постачальника у формулі немає.
- Сигнали: схожість найближчого тексту, умови запиту, місце нижче топ-10, запит від 6 слів. Окремо: збіг за кодом 100%, а код, що є в N постачальників (553 коди з 4-5 цифр, 1099 моделей), 100/N кроком 5%: 2 це 50%, 3 це 35% (картка пише «код є в N постачальників»); `hasCloseMatch: false` 5%, «не підходить» за умовою 25%, фото без тексту лише за місцем. Це заміри на Gemini з читанням запиту: інша модель чи текст без читання (збій чи `parseQuery: false`) дає `confidence: null`, крім збігу за кодом, і картка без рядка.
- Формулу й числа нижче міряно на Axpol і Midocean (6,5 тис. моделей), коли другий прохід за фактами був типово увімкнений (до 2026-11-06). На 7 постачальниках (аналіз 2026-11-06, без оцінок людей) середня впевненість карток топ-24 на нейтральних запитах за категорією: Axpol 81,6%, Macma 80,1%, Blue Collection 79,1%, Inspirion 78,3%, Easy Gifts 78,2%, Midocean 77,1%, Makito 75,8%; різниця невелика, причина та сама, що в нахилу показу (тексти Axpol ближчі до запиту). ## Перевірка
`pnpm run check`: typecheck, lint, тести і build. Без нього зміна не вважається готовою.
